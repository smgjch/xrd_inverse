# v0.2：有限观测与未知仪器参数

v0.2 沿用 v0.1 的理想化原型、±5% 独立均匀晶格先验、Cu Kα₁ 波长、4096 点 10–90° 轴、Gaussian 峰形与 Poisson 计数模型。新增条件针对有限观测及仪器参数歧义，不扩展到未知原型、混相或全结构生成。

## 发布与兼容性

工具版本为 `0.2.1`，数值协议仍为 `xrdbench-0.2.0`。完整 pilot 数据（含全部 test 标签）已发布到 [PXRD-LatticeBench](https://huggingface.co/datasets/smgjch/PXRD-LatticeBench)，发布版本为 `v0.2-pilot`。下载和字段说明见 [数据使用指南](数据下载与使用.md)。`generate --suite` 支持 `v0.1`、`v0.2`、`v0.1+v0.2`。v0.1 的数值模拟规则和每个观测的随机流保持兼容；新软件重新生成的 manifest 会记录新的生成器指纹，因此 dataset_id 不会冒充历史发布 ID。旧发布及其合法预测仍可由新版 evaluator 评分。

新版本只支持 rutile-(a,c) 和 ZnO-(a,c)。Si-a 保留在 v0.1，避免将本来很容易的单峰一参数定位称为新的困难任务。

## 六个新增 ID 条件

| 条件名 | rutile 观测 2θ 区间 | ZnO 观测 2θ 区间 | E |
| --- | --- | --- | --- |
| hard_mixed_e100 | [33,39]° | [45,50]° | 100 |
| hard_mixed_e300 | [33,39]° | [45,50]° | 300 |
| hard_mixed_e1000 | [33,39]° | [45,50]° | 1000 |
| hard_paired_e100 | [33,39]° ∪ [52,57]° | [33,37]° ∪ [45,50]° | 100 |
| hard_paired_e300 | 同上 | 同上 | 300 |
| hard_paired_e1000 | 同上 | 同上 | 1000 |

窗口固定在绝对角度，不随测试真值或峰位置移动。缺测填零且 mask=False。`mixed` 表示以混合指数反射提供参数组合约束的窗口设计，**不表示已认证为混相或多峰后验**；实际峰进入/离开窗口以及模式形态随参数变化。E 是单位相对积分峰的曝光尺度，不是全谱总计数或 SNR。

两个窗口方案提供信息量梯度；三档计数提供统计噪声梯度。所有六种条件都进入训练和 validation，因此这里首先比较困难 ID 推断，而不是只比较未知噪声 OOD。

## 两条赛道与公平性

v0.2 每条观测按下表独立于 θ 采样 nuisance：

| 参数 | 先验 |
| --- | --- |
| FWHM | Uniform(0.15,0.60)° |
| 零位偏移 | Uniform(-0.10,0.10)° |
| 强度尺度 | LogUniform(0.7,1.3) |
| 背景密度 | Uniform(0.003,0.02) /° |
| 背景斜率 | Uniform(-0.4,0.4) |

`calibrated` 和 `blind` 使用完全相同的 θ、nuisance 和 Poisson 随机实例。前者提供五个实际 nuisance 数值，后者提供 NaN 和 known=False。由此得到的差异可以归因于仪器信息是否公开。两条赛道分别训练、分别报告，模型不读取 condition、group ID、隐藏 nuisance 或测试标签。

v0.1 仍沿用历史 nuisance 规则，不为了这种配对而回改旧任务。v0.2 的先验在每个新增 condition 的 manifest 配置中明确给出。联合版本包含两组条件先验，物理方法必须按实际观测设计处理；不得无条件套用旧 blind 先验。

manifest 的 `nuisance_priors_by_domain` 明确给出各域先验；联合版本的顶层 `blind_nuisance_prior` 为 null，表示不存在单一共享先验。v0.2/联合版本的 `calibrated_nuisance` 为 null，实际已知 nuisance 以每条观测为准。窗口和曝光是公开测量设计，可据此识别适用的观测模型，但不能读取隐藏仪器真值。

现有 `score --physics-k` 仍仅支持 calibrated。blind 的原始点预测、后验及校准评分可正常工作；本版没有把粗略 nuisance profile 当作边缘后验，也没有提供认证的 blind 物理参考。合作者可接入独立的积分/SMC/MCMC 方法，但须提交收敛与混合诊断。这是本次 pilot 结果解释的明确限制。

## 0.1 / 0.2 / 0.1+0.2 的含义

三种训练集合具有相同的独立 θ 数量和每结构两次固定增强：

- v0.1：两次增强都从旧六个 ID 条件抽取。
- v0.2：两次增强都从新增六个 ID 条件抽取。
- v0.1+v0.2：保留 v0.1 的第一个训练观测和 v0.2 的第二个训练观测，严格一半来自每个域。不能把两份完整训练集直接拼接后称为同预算比较。

三种版本的 θ 流与结构分组相同，train/val/test 互不重叠。联合版的每个观测 ID、噪声、mask 与单独版相应观测完全相同。validation：旧版每结构 6 张，新版 6 张，联合版 12 张。test：旧版含 OOD/stress 共 11 张，新版 6 张，联合版共 17 张。

主要成绩仅计算各版本 ID 条件。联合成绩对两个域各给 50% 权重；由于每域恰有六个 ID 条件，按全部 12 个 ID 条件等权平均与该规则等价。旧 OOD/stress 单独报告，不混入主平均值。

每个训练版本都在同一联合测试发布上推理，随后分别统计旧版、新版及联合域，形成 3×3 训练/评测矩阵。主表对角线表示每个版本各自训练、各自测试；跨域结果表示条件分布迁移，不是跨晶体原型泛化。

## 数据规模与训练责任

本轮生成 pilot：每原型、每赛道、每训练版本有 5000 个独立训练结构（10000 条谱）、512 个 validation 结构和 512 个 test 结构。`smoke` 与 `main` 规模也可通过生成器选择。pilot 不等于论文主规模。

**本轮仅交付任务、数据、接入与汇总工具，不训练 baseline，也不提供尚不存在的性能。** 各方法由合作者在自己的环境训练。训练时保存训练 dataset_id、training_suite、training_seed、模型代码版本、checkpoint 哈希和预算。正式方法比较需统一预算与验证集选择规则，按 v0.1 指南保留必要的强基线和消融。

“在三个版本上汇报性能”首先指三个评测域：一份联合测试集预测即可产生 v0.1、v0.2、联合成绩，**不要求重复训练三次**。若进一步研究训练数据配方，可分别采用三种训练集，形成 3×3 矩阵；该实验为可选扩展，不是汇总工具的前提。

训练只读 public/train 和 public/val 标签。当前 HF 发布中的 private/test 标签完全公开，目录名为兼容旧工具保留；合作者可自行评分，但 test 不得用于训练或调参。这是开放研究评测，不是隐藏标签盲测；接口隔离也不是对任意 Python 代码的安全沙箱。不同种子单独列出，结构 bootstrap CI 不包含训练种子方差。

## 合作者运行方式

```bash
python -m venv .venv
. .venv/bin/activate
pip install -e '.[test,hub]'
pytest -q

# 下载共同冻结数据；不各自重新生成测试集。
export XRD_DATA_ROOT="$PWD/data"
xrdbench download --all --output "$XRD_DATA_ROOT"
```

在原模型环境训练和推理即可，不要求安装同一套 PyTorch。将模型接入 adapter 或导出离线 NPZ，参见 [接入指南](实验协议与接入指南.md) 与 [元数据模板](../examples/method_metadata.json)。以下流程没有训练动作：

```bash
export XRD_PUBLIC="$XRD_DATA_ROOT/rutile/blind/v0.1+v0.2/public"
export XRD_PRIVATE="$XRD_DATA_ROOT/rutile/blind/v0.1+v0.2/private"

# 合作者在自己的环境导出已有模型的预测；MODULE:Adapter 替换为自己的实现。
xrdbench run --public "$XRD_PUBLIC" --adapter MODULE:Adapter \
  --checkpoint model.pt --metadata method.json --kind posterior \
  --output "$XRD_RUN_ROOT/method_a/prediction"
xrdbench validate --public "$XRD_PUBLIC" --submission "$XRD_RUN_ROOT/method_a/prediction"

# 使用下载包中公开的测试标签评分；标签不传给模型。
xrdbench score --public "$XRD_PUBLIC" --private "$XRD_PRIVATE" \
  --submission "$XRD_RUN_ROOT/method_a/prediction" --output "$XRD_RUN_ROOT/method_a/score"

# 一份联合发布上的评分自动拆成三个域；可同时输入多个方法、种子、原型和赛道。
xrdbench summarize --scores "$XRD_RUN_ROOT/method_a/score" \
  --output reports/collaborator_results
```

输出 `matrix.csv`、`conditions.csv`、`results.json`、`report.md`。`matrix.csv` 每份提交三行；保存训练版本、种子、评测版本和数据指纹。旧 OOD/stress 只进入分条件表。不会自动填补缺失的方法、推断未登记的训练配方或运行 prior 代替真实模型。

汇总要求每个 checkpoint 在联合 test 发布上完成一次评分。同一原型、赛道、view 的方法必须使用完全相同的数据指纹，重复提交、validation 冒充 test、不同发布混排、条件覆盖不齐均拒绝。不同 view 明确分列，不能直接排名比较。先按单独版本预测的合作者需在联合 public/test 上重新推理即可，无须重训。

需要方法间成对比较时，使用相同联合发布的两份评分，`compare --condition` 支持 `v0.1`、`v0.2`、`v0.1+v0.2`；例如 `xrdbench compare --a score_a --b score_b --condition v0.2 --metric energy_score`。点模型不能比较后验 energy score。

跨训练/评测版本时，adapter 应核对原型、参数顺序、先验、谱轴和赛道，并显式允许目标评测 dataset_id。元数据保留真实训练 dataset_id，不把它改写成评测 ID。示例 PyTorch adapter 支持 checkpoint 的 `allowed_evaluation_dataset_ids`；默认仍只接受自身 dataset_id。

## 结果解释与发布

报告平均相对误差（明确乘 100 为 %）、各参数 Å 误差、0.1%/0.5% 成功率、energy score、90% 覆盖率及区间宽度、条件级结果、训练和推理成本。后验点估计统一取样本边缘中位数。oracle@K 仍仅为辅助指标。

后续模型结果应结合完整 validation 曲线判断是否充分收敛；不能凭有限预算 pilot 宣布一个方法的能力上限。对低信息任务，点误差大并不等于后验方法失败；需和 prior、覆盖率及宽度一起解释。新增窗口尚未经过全先验的认证多峰后验审计，结果不得直接写成“已证明恢复全部多峰”。

`.gitignore` 保留源码、依赖锁文件、文档和小型 CSV/JSON 结果，排除数据、模型、预测、运行日志、环境、密钥与部署配置。数据和 checkpoint 应作为独立版本化资产分享。公开仓库前以 `git status` 检查待提交文件；`.gitignore` 不会移除已经跟踪的文件。
