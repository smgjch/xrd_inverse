# PXRD-LatticeBench 数据下载与使用

数据仓库：[smgjch/PXRD-LatticeBench](https://huggingface.co/datasets/smgjch/PXRD-LatticeBench)。发布版本：`v0.2-pilot`，数据许可证：Apache-2.0。

本次发布覆盖现有全部 12 个 pilot 配置、全部训练/验证/测试谱和对应晶格参数标签。它不包含尚未生成的 main 数据、真实实验谱或模型权重。文件清单、每个配置的 dataset_id、行数、SHA-256 均见数据仓库的 `publication.json`；本仓库的 `reports/huggingface_release.json` 记录冻结的 Hub commit。

## 方式一：用于统一 evaluator 的原始 NPZ

```bash
git clone https://github.com/smgjch/xrd_inverse.git
cd xrd_inverse
python3.11 -m venv .venv
. .venv/bin/activate
pip install -e '.[hub]'

xrdbench download --task rutile --track blind --suite v0.1+v0.2 \
  --output data/rutile/blind/v0.1+v0.2
# 或全部 12 个配置，--output 下自动组织 <task>/<track>/<suite>。
xrdbench download --all --output data
```

原型选 `rutile` / `zno`，赛道选 `calibrated` / `blind`，版本选 `v0.1` / `v0.2` / `v0.1+v0.2`。单配置下载时 `--output` 就是该配置的根目录。`--all` 会创建三层目录。无需 Hugging Face token；不要把凭证写入代码或配置。

默认下载不可变 commit；切换版本可显式传 `--revision`。`--cache-dir /path/to/cache` 可把下载缓存放在大容量盘，`--output` 可同时指向该盘；解压内容与 Hub 缓存会各占一份空间。首次下载后可以离线运行 evaluator。重复下载会校验并复用现有完整目录；目录存在但损坏或属于其他发布时会报错，请改用新的输出目录。

```text
<release>/
  public/
    manifest.json
    prototype.cif
    train/observations-*.npz, targets-*.npz
    val/observations-*.npz, targets-*.npz
    test/observations-*.npz
  private/
    manifest.json
    test/targets-*.npz
```

`val` 是历史文件布局中的 validation。CLI 的 `run`、`reference-grid`、离线导出及 Python 读取接口同时接受 `val` 和 `validation`，提交 manifest 仍保存 `val`，以兼容旧预测。`private` 也只是历史目录名：本次 HF 发布包含其中的全部测试标签，任何人都可以下载评分。它不是隐藏测试集或受控排行榜。

```bash
XRD_RELEASE=data/rutile/blind/v0.1+v0.2
xrdbench audit --public "$XRD_RELEASE/public" --private "$XRD_RELEASE/private"

# 替换成自己的 adapter、checkpoint 与元数据；此命令只执行推理。
xrdbench run --public "$XRD_RELEASE/public" --adapter MODULE:Adapter \
  --checkpoint model.pt --metadata method.json --kind posterior \
  --split test --output outputs/my_method/prediction
xrdbench score --public "$XRD_RELEASE/public" --private "$XRD_RELEASE/private" \
  --submission outputs/my_method/prediction --output outputs/my_method/score
xrdbench summarize --scores outputs/my_method/score --output reports/my_method
```

在联合 test 上提交一次预测，即可得到 v0.1、v0.2、等权联合成绩；无需为汇总重复训练。validation 评分无需 `--private`。测试标签仅供最终评价，不得用于训练、选择超参数、选 checkpoint 或挑选后验样本。

## 方式二：Hugging Face datasets / Parquet

原方法可以只安装 `datasets`，不依赖 pymatgen 或本 evaluator：

```bash
pip install 'datasets>=3.6,<5'
```

```python
from datasets import load_dataset

ds = load_dataset(
    "smgjch/PXRD-LatticeBench",
    "rutile-blind-v01-v02",
    revision="v0.2-pilot",
)
print(ds)  # train=10000, validation=6144, test=8704
train = ds["train"].with_format("numpy")
counts, mask, theta = train[0]["counts"], train[0]["mask"], train[0]["theta"]
```

12 个配置名遵循 `{rutile|zno}-{blind|calibrated}-{v01|v02|v01-v02}`。需要严格固定发布时，将 `revision` 换成发布记录中的 40 位 commit；`streaming=True` 可用于流式读取。

Parquet 是原始 NPZ 的无损表视图。所有 split 都包含 `theta`；train/validation/test 的划分与原始发布完全一致。保持 `ids` 和预测的对应关系，导出时使用原始包中的 manifest 与统一 `SubmissionWriter`，不要随机重新划分所有行。`metadata/<config>/manifest.json` 提供完整物理配置、谱轴、条件先验和数据指纹，`prototype.cif` 提供理想化原型。

| 字段 | 类型与含义 |
| --- | --- |
| `ids` | 唯一观测 ID；用于预测对齐 |
| `group_ids` | 独立结构 ID；用于分组检查/bootstrap，不作为模型输入 |
| `condition` | 观测条件；用于分层报告，不作为标准模型输入 |
| `counts` | uint32[4096]，Poisson 计数；缺测位置为 0 |
| `mask` | bool[4096]，True 表示已观测 |
| `exposure` | float64，公开曝光尺度；不是全谱总计数 |
| `nuisance` | float64[5]，依次为 FWHM (°)、零位偏移 (°)、强度尺度、背景密度 (/°)、背景斜率 |
| `nuisance_known` | bool；calibrated 为 True，blind 为 False |
| `theta` | float64[2]，目标 `(a,c)`，单位 Å |

谱轴为 `np.linspace(10, 90, 4096)`，表示 2θ (°)；Cu Kα₁ 波长 1.5406 Å。blind 的 nuisance 五维均为 NaN；不要将其误当作缺失标签。模型可读取 counts、mask、exposure 及赛道允许的 nuisance，不能读取 theta、condition 或 group_ids 作推理特征。

## 版本、规模与公平比较

每个配置有 train/validation/test = 5000/512/512 个独立结构。谱数为：

| suite | train | validation | test |
| --- | ---: | ---: | ---: |
| v0.1 | 10000 | 3072 | 5632 |
| v0.2 | 10000 | 3072 | 3072 |
| v0.1+v0.2 | 10000 | 6144 | 8704 |

共存储 238,784 行，但版本和赛道间存在有意的结构/观测复用，这不是 238,784 个独立晶体。train、validation、test 的结构集合互不重叠。联合训练配方每结构各取一条旧/新域观测，保持 10000 条预算；直接拼接两份完整训练集会改变预算。不同原型、赛道、view 分开报告。

v0.1 测试含 6 个 ID 与 5 个 OOD/stress 条件；v0.2 含 6 个困难 ID 条件；联合主成绩只对两域 ID 各给 50% 权重，旧 OOD/stress 单列。blind 的原始预测可评分，公共物理候选评分目前仅支持 calibrated。详见 [v0.2 协议](v0.2实验协议.md)。

## 发布校验

原始包保留原有文件字节、dataset_id 与标签布局。下载器核验 archive SHA-256、路径安全、manifest 指纹和所有原始文件 SHA-256；Parquet 转换已逐行逐字段与 NPZ 比较，包括 NaN 和全部 test 标签。数据仓库提供 `SHA256SUMS`。

维护者可用 `python -m examples.prepare_hub_release --source <frozen-archives> --output <new-stage>` 重建 Parquet 视图；该脚本需另装 `pyarrow==19.0.1`，只转换与验证，不上传、不训练。已有数据应始终以发布文件为准，不依赖新环境重新模拟。
